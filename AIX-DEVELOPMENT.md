# AIX-DEVELOPMENT.md — everything about the kit itself

**Audience:** whoever is developing or refining AIX (the framework), typically in a coding agent session.
**Not for:** agents building an application *with* AIX. This file is deliberately absent from `AGENTS.md`,
every `INDEX.md`, and the `--into` installer payload, so it never enters an app project's context.

If you are an agent and the user said "read AIX-DEVELOPMENT.md", you are working **on the kit**. Rules for that
are in §9. Do not run `core-session-resume` (that's for app work); there is no STATE.md for kit development.

---

## 1. What AIX is

A language-agnostic, clone-and-go framework for Specification-Driven Development with AI coding agents
(opencode, VS Code/Copilot, Claude Code, Cursor, …). Documentation is the ground truth; code is its optimised
implementation. The overriding design constraint is **minimal resident context per turn**: the corpus may be
large, but an agent should hold ~3k tokens of it permanently and load the rest surgically, on demand.

## 3. Design principles and the reasoning behind them

1. **Resident floor, not corpus size, is the metric.** Always-resident = `AGENTS.md` (~1.2k tokens) + runtime's skill
   name/description list (~1.2k after trimming) ≈ 2.5–3k. Everything else loads per turn.
2. **Navigate, never scan.** Ladder: AGENTS nav table → folder INDEX (≤40 rows, "read when / skip when") → grep by ID → `grep -n "^## "` → open file. Forbidden: `ls -R`, `find .`, reading whole `coverage-matrix.md` or `vulnerability-register.md`.
3. **Paths are the API.** Domain folder names are identical across `docs/requirements/functional/`, `docs/requirements/api/`, `docs/tests/*/`, `backend/app/`, `frontend/src/features/`. "Where is the invoice service?" is a path guess, not a search.
4. **Everything has a stable ID and a grep-able trail.** `FR/NFR/API/DM/ADR/TS/VUL/TASK/CONFLICT`; code markers `@implements`, `@tests`, `@mitigates`. Scripts, not LLM reads, compute traceability.
5. **Requirements win; humans decide.** Authority order; conflicts are recorded (`CONFLICT-*`, scope frozen) before the user is asked; rulings become ADRs.
6. **Evidence gates status.** VUL → `addressed` only with audit report + negative test; TS → `automated` only with `@tests` marker; FR → `verified` only when its TS are green.
7. **Skills are small and hand off.** Each names its reading budget, inputs, procedure, outputs, next skill. Orchestrators (`core-sdd-workflow`, `implement-feature`, `testing-plan-tests`, `security-audit`) choose sub-skills so bodies never stack.
8. **Short sessions by design.** One task per session; `core-session-handoff` at ~60 % context; restart costs ~7–10k tokens because `STATE.md` + task `context_files` name exactly what to load. Per-turn cost = whole window resent, so many short sessions beat one long one on total tokens too.
9. **Deterministic before generative.** If a grep/script can do it (scans, coverage, validation), the skill runs the script and reasons only about its output.
10. **One vocabulary.** `field-dictionary.md` is the only source of field names; validator warns on strays.

## 4. Key mechanisms (how they actually work)

- **Skill install**: leaf dir `skills/a/b/` → name `a-b` (validator enforces `name:` == path). Symlinks by default, `--copy` on Windows/CI. Targets: `.opencode/skills`, `.claude/skills`, `.github/skills`, `.agents/skills`, `.cursor/skills`. Pointer files: `CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, `.cursor/rules/aix.mdc`. Runtime facts verified 2026-09-04: opencode reads `.opencode/skills` and `.claude/skills`; VS Code reads `.github/skills`, `.claude/skills`, `.agents/skills` (setting `chat.useAgentSkills`). Verified 2026-09-05: Antigravity reads `.agents/skills` (default; `.agent/skills` legacy) and `AGENTS.md` directly (since 1.20.5); Gemini CLI reads `.gemini/skills` or the `.agents/skills` alias (alias wins on name clash) and `GEMINI.md` as context file (`context.fileName` in `.gemini/settings.json` could point it at AGENTS.md, but a pointer file needs no per-user setting).
- **Register statuses**: `expected → unverified | confirmed → mitigated → addressed`, plus `accepted` (ADR with owner + review condition) and `not-applicable` (justified). Release gate: no internet-facing row left before `addressed/accepted/not-applicable`.
- **Requirement lifecycle**: `draft → approved → implemented → verified → superseded`. Only the user approves.
- **Road-map**: `pending/{ideas,backlog,next} → going-on ⇄ blocked → completed/YYYY-MM`; `roadmap.py` moves files and rewrites `STATE.md` fields. Task template carries `context_files`, files changed, verification performed, exact next actions.
- **Conflicts**: `.aix/templates/conflict.md` → `docs/conflicts/open/`; 3-column table; options A (change code, default) / B (change spec → ADR) / C (split); human decision; ADR; move to `resolved/`.
- **Validator checks**: front-matter present; skill name==path; every docs folder has INDEX and lists its files (road-map task files exempt); relative links resolve; TS `covers` reference existing IDs; VUL statuses valid; DM/API field names exist in the dictionary (warning).
- **Coverage matrix**: regex scan of `backend frontend shared infra src app tests` for markers; table per requirement with gaps `no test spec | no code | spec not automated`; orphan TS list; VUL mitigations found.

## 5. Provenance: what came from where

Built 2026-09-04/05 in a chat session, then compared against two alternative designs the user obtained.

**From the ChatGPT design ("agentic-sdd-framework", 65 files, 39 KB) — adopted:** authority order; `docs/conflicts/` as first-class queue; extra VUL states and richer audit-report fields; requirement sections (actors & permissions, data & privacy, security & observability) and `verified` state; task fields (files changed, verification performed, exact next actions); `blocked/` folder; `docs/operations/`; allowed/forbidden dependency lines in code-root READMEs; trimming `AGENTS.md` (~440→290 words) and skill descriptions (1,565→896 words).
**Rejected:** top-level `domain/application/infrastructure/` split (per-domain folders keep paths guessable); relying on `.agents/skills` alone; its 16 skills (bodies were identical boilerplate) and principle-only meta-docs (~1,300 words total, no executable tooling).

**From the Gemini design (essay + bootstrap script) — adopted:** canonical field dictionary to stop field-name hallucination; deterministic `.aix/scripts/` inside audit skills; Cursor support; blunt "no heavy compute in a request handler" rule; "ADRs are settled" wording.
**Rejected:** controllers as business-logic holders (fat-controller anti-pattern, contradicts its own repository rule); numbered filenames (`01-…`, renames break links); custom `AI_MANIFEST.md` name and deprecated `.cursorrules` (runtimes auto-read `AGENTS.md`; Cursor uses `.cursor/rules/*.mdc`); its claim that opencode needs bash-mapped tools (it reads `SKILL.md` natively); strictly one task in `going-on/` (AIX allows one per agent).

## 6. Known limitations (be honest with the user about these)

- Savings are **behavioural**: nothing mechanically stops an agent from scanning. AGENTS rule 2, `core-find-doc`, and per-skill budgets are nudges. Weaker models still wander. Not yet measured on real prompts.
- Stack docs are guidance, not code scaffolds. `architecture-structure-project` creates folders; there are no framework-specific starter files (FastAPI app factory, Alembic config, etc.).
- Skills have **not** been trigger-tested (no eval set). Descriptions were written for recall, then trimmed; recall after trimming is unverified.
- Audit `.aix/scripts/` are grep heuristics (false positives expected); only 3 of 10 audit skills have scripts.
- `validate.py` is regex-based (no YAML parser) and does not check `related:`/`depends_on:` targets, INDEX row accuracy, or file-size limits.
- Windows: symlinks need developer mode; `--copy` fallback duplicates skills (must re-run install after editing `.aix/skills/`).
- `coverage_matrix.py` cannot see tests that prove a TS without a marker; markers are a convention, not enforced by lint.
- No multi-repo story (frontend and backend in separate repos) — `shared/` assumes a monorepo.

## 7. Refinement backlog (suggested order)

1. **Trigger evals for skills**: 3–5 realistic prompts per skill; check the right skill loads and no wrong one does; adjust descriptions. Highest value, unblocks trusting the "skills save tokens" claim.
2. **Measure the ladder**: run 5 typical tasks (bug fix, new endpoint, new entity, audit, resume) and log files opened / tokens; compare against an unstructured repo. Put numbers in README.
3. **Stack scaffolds**: `.aix/scripts/scaffold.py --stack python-fastapi` producing app factory, composition, settings, core/errors, memory adapter, contract test skeleton, importlinter contract, Makefile targets. Same for `js-react`, later `java-spring`.
4. **Validator upgrades**: proper YAML front-matter parsing; `related`/`depends_on` existence; file ≤300 lines / folder ≤12 files warnings; INDEX rows pointing at missing files; FR `implemented`/`verified` vs markers/TS status; `STATE.md` staleness vs git.
5. **Scripts for the other 7 audit skills** (authn/authz endpoint check for `{id}` routes without service-level `can(`; input-validation schema strictness; web headers via HTTP client; logging sensitive-field grep; AI tool registry permission dump; infra: hadolint/checkov/trivy runners; data-privacy PII field grep).
6. **Lint enforcement of layering** shipped as config: `backend/importlinter.toml` template, `dependency-cruiser` config, ArchUnit example.
7. **Pre-commit config** template calling validate + secrets scan.
8. **Multi-agent STATE.md** semantics (one line per agent) and a `roadmap.py claim` command.
9. **Delete-example command** (`.aix/scripts/roadmap.py` or new script) removing the EXAMPLE domain cleanly (docs, INDEX rows, dictionary rows).
10. Consider generating INDEX tables from `read_when:` front-matter so INDEX text never drifts.

## 8. Decisions log for the kit itself (mini-ADRs)

| # | Decision | Why |
|---|---|---|
| K1 | Single hierarchical `.aix/skills/` source; flatten on install | Runtimes require flat `skills/*/SKILL.md`; humans want categories; symlinks reconcile both |
| K2 | `AGENTS.md` is the only entry point; other files are pointers | It's the name every runtime auto-reads; one place to edit |
| K3 | Per-domain folders with layers inside, not top-level layers | Locality: fixing users touches `app/users/` only; path guessing beats search |
| K4 | Memory adapter mandatory per domain | Makes unit tests I/O-free and defines the port by contract tests |
| K5 | Conflicts recorded before asking | Freezes scope for parallel agents; keeps history even if the chat is lost |
| K6 | Statuses change only with evidence files | Prevents "marked done" drift; auditable |
| K7 | Scripts over LLM for scanning/traceability | Near-zero tokens, deterministic, repeatable |
| K8 | Skill names carry category prefix | Trigger clarity and namespace hygiene across four install targets |
| K9 | Keep "sdd" in `core-sdd-workflow` after renaming kit to AIX | "sdd" = spec-driven development, still accurate |
| K10 | This file excluded from `--into` payload and from all INDEXes | Zero interference with app projects |
| K11 | Antigravity and Gemini CLI via the existing `.agents/skills` target plus a `GEMINI.md` pointer; no `.gemini/skills` target | Both runtimes already read `.agents/skills`; a second copy would be redundant and lose on Gemini's alias precedence anyway. Pointer file beats asking every user to edit `.gemini/settings.json` |

## 9. Working on the kit (rules for the developing agent)

- Edit `.aix/skills/` only; never the installed copies. After editing skills or templates run `aix install` (idempotent) and `aix docs validate` (must be 0 errors; investigate warnings).
- Skill `name:` must equal `<category>-<folder>`; keep descriptions ≤ ~30 words with trigger phrases; bodies: *When NOT / Inputs / Procedure / Outputs / Hand-off* + reading budget; no duplication of meta-docs (link instead).
- Docs: front-matter per `.aix/meta-docs/conventions/document-format.md`; every new file gets an INDEX row; ≤300 lines; stable H2 names.
- Never reference this file from `AGENTS.md`, INDEXes or skills. Keep `KIT_PAYLOAD` in `.aix/scripts/install_skills.py` free of it.
- Bump `.aix/config.yaml` version and add a `CHANGELOG.md` entry per change set.
- Smoke test after changes: `./.aix/bin/aix install && ./.aix/bin/aix docs validate && ./.aix/bin/aix docs coverage && ./.aix/bin/aix task list`, plus `./.aix/bin/aix install --into /tmp/x` on a scratch dir.
- Before shipping: remove generated dirs (`.opencode .claude .agents .github/skills .cursor`) — they are git-ignored and regenerated by the installer.
- When the user asks "does this save tokens?", answer in terms of resident floor + per-turn loads + session restarts (§3.1, §3.8), and flag §6 honestly.

## 10. Numbers to remember

Resident floor ≈ 2.5–3k tokens. Typical locate-and-read ≈ 2.5k. Session restart ≈ 7–10k. Skill bodies 300–900 tokens each, one or two loaded at a time. Meta-docs full architecture read ≈ 900 lines (design sessions only). 162 files in the kit, ~180 KB, 36 skills, 24 seeded VUL rows, 4 example requirements/TS.
