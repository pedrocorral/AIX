# tests/ — what must be proven (TS-*), and how well we do
Read this when: planning/writing/reviewing tests, releasing. Skip when: docs-only change.

| Path | What | Read when |
|---|---|---|
| `functional/` | TS per domain proving FR/API acceptance criteria (unit/integration/functional levels live inside each TS via `level:`) | Feature work |
| `non-functional/` | TS proving NFRs: security, performance, observability, accessibility, AI evals | Release; NFR work |
| `dependency-graph.md` | Generated by `aix graph --report`: excess above ground state, cycles, hubs, propagation cost | Design reviews; release |
| `coverage-matrix.md` | Generated by `aix coverage`: FR → TS → code → gaps. **grep your ID, do not read whole** | Closing tasks; release |
| `test-plan-rules.md` | How TS are numbered, levelled and de-duplicated | Writing a TS |
