# tests/ — how the kit is proven
Read this when: changing a command; releasing. Skip when: docs-only change.

| Path | What | Read when |
|---|---|---|
| `suite.md` | Map of the automated suite (`tests/` at the repo root, `aix self-test`): file per area, what each proves, what is not covered | Before changing a command |
| `functional/`, `non-functional/` | Reserved for `TS-*` specs of the CLI | When a spec is written |
| `coverage-matrix.md` | Generated by `aix docs coverage` | Release |
| `code-style.md` | Generated by `aix code style --report`: the kit's own readability table | Dogfooding, release |
| `test-plan-rules.md` | How TS are numbered and levelled | Writing a TS |
